## What is Qdrant?

Qdrant is an open-source vector database and similarity search engine, written in Rust and released under the Apache 2.0 license, with a managed Qdrant Cloud service. 

**Qdrant** stores embeddings together with a JSON payload for each point and serves nearest-neighbor search over them through REST and gRPC APIs. It is commonly used for semantic search, recommendations, and the retrieval step of Retrieval-Augmented Generation (RAG).

## Core Architecture and Mechanics

Qdrant's design centers on a few features:

* **Stores high-dimensional vectors (embeddings) generated by machine learning models, grouped into collections.** A collection can be split into shards and replicated across nodes in a distributed deployment.
* **Executes similarity searches with an HNSW graph index to find the closest vectors quickly.** Quantization options reduce memory use for large collections.
* **Combines dense vector retrieval with sparse vectors for keyword-style matching in 'Hybrid Search'.** Results from both can be fused, and payload filters narrow results by fields like category or date during the search.

In a lakehouse architecture, embeddings are often produced and governed in [Apache Iceberg](/knowledgebase/apache-iceberg/) tables and then loaded into Qdrant for low-latency serving.

## Why Qdrant Matters in the Modern Data Stack

Vector databases often serve as the retrieval layer for AI applications, letting large language models search an organization's own documents and ground their answers through RAG. Good retrieval improves accuracy but does not prevent every wrong answer.

Qdrant can run as a single container for development, as a distributed cluster on Kubernetes, or as a managed service, so teams can start small and grow without changing their application code.

### Key Benefits
- **Filtered Search:** Payload filters are applied during the vector search, not only afterward.
- **Open Source:** Apache 2.0 licensed, with self-hosted and managed options.
- **Hybrid Retrieval:** Dense and sparse vectors in the same collection.

## Frequently Asked Questions

### How is a vector database different from a relational database?
Instead of searching for exact string matches, vector databases search for conceptual similarity based on proximity in high-dimensional space. Most vector databases, including Qdrant, use approximate nearest neighbor indexes that trade a small amount of recall for speed.

### What is an embedding?
An embedding is a representation of text, images, or audio as a list of numbers produced by a machine learning model, arranged so that items with similar meaning end up close together.

### How does Qdrant impact data governance and security?
Qdrant supports API key authentication and JWT-based access control that can limit a token to specific collections and read or write access. Governance of the source documents, such as lineage and retention, usually lives upstream in the lakehouse catalog.
