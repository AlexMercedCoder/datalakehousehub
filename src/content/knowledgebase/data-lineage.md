# What is Data Lineage?

Data Lineage is the record, often shown visually, of the lifecycle of data. It tracks where data originated, how it was transformed, what logic was applied to it, and where it is consumed across the enterprise architecture.

In a decentralized [Data Lakehouse](/data-lakehouse/), data engineering pipelines are complex. Data is extracted from an external Salesforce API, landed in a raw Amazon S3 bucket (Bronze), cleaned using PySpark (Silver), joined with legacy financial data, modeled into a Star Schema using dbt (Gold), and finally pushed into many executive Tableau dashboards. If a CEO discovers an obvious numerical error on their dashboard, tracking down which line of code or which API caused the failure is like searching for a needle in a haystack. Data Lineage provides the map that makes this search much faster.

## Automated Extraction and Graph Construction

Historically, organizations attempted to manage data lineage manually in Excel spreadsheets or static Confluence wikis. This rarely worked; the documentation went stale as soon as an engineer pushed a new code commit to production.

Modern Data Lineage is largely automated. It relies on Metadata Catalogs (like Unity Catalog, Atlan, or Collibra) and open standards like OpenLineage that collect metadata from the operational infrastructure.

### Parsing the Codebase
The catalog connects to the execution engines. It parses the SQL in Snowflake query history, the Directed Acyclic Graphs (DAGs) generated by Apache Airflow, and the dependency references (`{{ ref() }}`) defined in dbt. 

### Building the Dependency Graph
It takes this metadata and constructs a Directed Acyclic Graph (DAG) of the data flow. It maps the columns from the raw tables to the columns in the analytical models, tracing the transformations step by step.

## Root Cause Analysis and Impact Analysis

Data Lineage serves two distinct operational functions for data engineering teams.

### 1. Root Cause Analysis (Tracing Backwards)
When a failure occurs, lineage provides Root Cause Analysis. If a data observability tool (like Monte Carlo) alerts the engineering team that the `Total_Revenue` column on the Gold dashboard suddenly contains negative numbers, the engineer opens the lineage graph. They trace the flow backward from the dashboard, through the Gold tables, through the Silver aggregations, until they identify the Bronze staging table that ingested a corrupted CSV file from a third-party vendor. Lineage shortens the search for the source of the error.

### 2. Impact Analysis (Tracing Forwards)
Conversely, lineage allows engineers to conduct proactive Impact Analysis. If a software engineering team decides they need to delete the `legacy_customer_id` column from the operational PostgreSQL database to save space, they must know what will break downstream. 

The data engineer uses the lineage graph to trace the specific column forward. The graph reveals that deleting that column will break the nightly dbt transformation pipeline, which will in turn break three machine learning models and the main executive marketing dashboard. The engineer can hold the software deployment until the downstream dependencies are refactored.

## Lineage and Regulatory Compliance

Beyond debugging, regulated industries like banking and healthcare often need lineage to meet regulatory expectations (for example, the BCBS 239 principles for bank risk data). 

If a European citizen invokes their "Right to be Forgotten" under GDPR (General Data Protection Regulation), the enterprise must erase that customer's personal data wherever it is held, unless an exemption applies. Data Lineage helps compliance officers locate the downstream tables, materialized views, and data products that ingested the customer's data, so the erasure can be complete and auditable.

## Summary of Technical Value

Data Lineage is the navigational map for the modern data architecture. By automatically parsing code and metadata to construct visual dependency graphs, it changes how organizations manage complex pipelines. It speeds up debugging through Root Cause Analysis, prevents many deployment failures through Impact Analysis, and supports regulatory compliance.
